一、为什么油管最难弄

抖音 / 快手 / TikTok 都是在一个「开放平台网站」里直接建应用；但 Google 把这件事拆成了三层，而且还要单独配一个「同意屏幕」，所以步骤最多：

「项目」 → 「开通 API」 → 「OAuth 客户端」 → 「同意屏幕」

这里的「项目」就是 Google 里"一个应用"的容器，只是名字叫"项目"，别被绕晕。

二、第 0 步：翻墙准备（最重要）

油管授权和发布，都需要后端服务器去调 Google 的接口（换 token、上传视频、查状态）。所以光浏览器能上 Google 不够，必须让后端程序也能上 Google。

很多同学卡在最后一步报 授权失败：fetch failed，原因就是：浏览器走了代理（翻墙软件），但后端程序没走，直接访问 Google 超时。

✅ 正确做法

  1. 打开你的翻墙软件（Clash / Clash Verge / V2RayN / Shadowrocket 等）。
  2. 把模式从「系统代理 / PAC」改成 「全局模式」（Global） 或 「TUN 模式」（虚拟网卡 / 增强模式）。
  3. 让 所有程序（包括 Node 后端）都走代理。
必须用「全局 / TUN」模式，不能用「系统代理 / PAC」模式——后两种只有浏览器等"遵守系统代理的软件"会走代理，Node 后端默认不遵守，照样连不上 Google。

三、第 1 步：创建 Google Cloud 项目

  1. 打开 Google Cloud 控制台，用你自己的 Google 账号登录（就是你想发视频上去的那个账号）。
  2. 看页面最顶部中间，点「选择项目」→ 弹窗右上角「新建项目」。
  3. 项目名随便起，比如 video-upload，点「创建」。
  4. 等顶部那行显示你刚起的项目名，再进行下一步。

四、第 2 步：开通 YouTube Data API

  1. 左侧菜单 →「API 和服务」→「已启用的 API 和服务」→ 点「＋ 启用 API 和服务」。
  2. 搜索框输入 YouTube Data API v3，点进去，点「启用」。

五、第 3 步：配置 OAuth 同意屏幕（新版界面）

Google 已经改版了！网上很多老教程写的「选 External → 点 Create」是老版本的按钮，新版里找不到。新版把这一步拆成了左侧菜单里的几个页面。

新版在 左侧菜单 有这些项（在「API 和服务」里，也可能叫「Google Auth Platform」）：

Overview      （总览）
Branding      （品牌信息：应用名、支持邮箱）
Audience      （受众：老版的 External / Internal 在这里）
Clients       （客户端：就是"凭据 / Client ID"）
Data access   （数据访问：权限 scope）
Security

① 点左侧「Branding」

  1. App name（应用名）：随便，比如 video-upload
  2. User support email（支持邮箱）：填你自己的邮箱
  3. 点 Save

② 点左侧「Audience」（老版的 External 在这里）

  1. 把受众类型选成 External。
  2. 找到 Test users，点「Add users」，填你自己的邮箱。
  3. 点 Save。
为什么要加"测试用户"：没正式上架的应用，Google 只允许"测试用户名单"里的人授权，不加自己就授权不了。

六、第 4 步：创建 OAuth 客户端，拿 Client ID / Secret

  1. 点左侧「Clients」，点「Create OAuth client」。
  2. Application type 选 Web application。
  3. 名称随便。
  4. 重点填下面的两个框（别填错框）：
最容易填错的一步！ 有两个长得很像的框，很多人把回调地址贴进了错的框里：
字段填什么
Authorized JavaScript origins
（授权 JavaScript 来源）		 留空，什么都不填（它只接受域名、不能带路径）
Authorized redirect URIs
（授权重定向 URI）		 填下面这一行（点「+ Add URI」再贴）： 
http://localhost:5001/platform/youtube/oauth/callback

填好后点 Create，弹窗会显示两个值，复制下来别关：

  • Client ID（客户端 ID）→ 对应系统的 appId
  • Client Secret（客户端密钥）→ 对应系统的 appSecret

七、第 5 步：填进系统「平台配置」页

  1. 打开我们系统的「平台配置」页：http://localhost:5173/#/platform-config（若要求登录，用 admin@qq.com / admin123）。
  2. 找到「油管 YouTube」这一行，点右边的「配置」按钮。
  3. 只填这两项，其它全部留空：
    • 应用ID（client_key / client_id） ← 粘贴 Client ID
    • 应用密钥 client_secret ← 粘贴 Client Secret
  4. 点「保存」。

八、第 6 步：点「授权」完成授权

  1. 回到表格，油管 YouTube 那一行点「授权」按钮，浏览器跳转到 Google。
  2. 选你刚才加进"测试用户"的那个 Google 账号。
  3. 大概率会弹红字警告 "Google 未验证此应用"：
    • 点左下角「高级 / Advanced」
    • 再点「前往 xxx（不安全）/ Go to xxx (unsafe)」
  4. 点「允许 / Allow」授权 youtube.upload 权限。
  5. 授权成功会自动跳回系统，弹绿色提示，油管那一行变成「已配置凭证」。

九、成功标志

  • 页面弹出：「油管 YouTube 授权成功，令牌已保存」
  • 「平台配置」表格里油管那一行的凭证状态变成 「已配置凭证」（绿色）
  • 刷新令牌（refresh_token）已自动存进数据库，之后发视频不再需要重新授权

授权成功后，回「视频发布」页选一个横屏（宽屏）视频，勾选「油管 YouTube」即可真实发布。

十、易错点汇总（踩坑大全）

坑现象 / 原因解决办法
fetch failed 点授权后报「授权失败：fetch failed」，后端连不上 Google 翻墙软件切到「全局 / TUN 模式」，让后端也走代理
找不到 External → Create Google 改版了，老教程的按钮没了 改去左侧菜单 Branding + Audience 配置
回调地址填错框 报 "Invalid Origin: must not contain a path" 回调地址填在 Authorized redirect URIs，JavaScript origins 留空
回调地址不匹配 Google 报 redirect_uri_mismatch 填的和系统里一字不差：http://localhost:5001/platform/youtube/oauth/callback
"应用未验证" 授权时弹红字警告 点「高级」→「前往 xxx（不安全）」继续
授权不了 / 账号被拒 账号没加进测试用户 去 Audience → Test users 加自己的邮箱
后端没启动 点授权后回调地址打不开 确保后端跑在 5001 端口（回调地址就是后端的地址）
