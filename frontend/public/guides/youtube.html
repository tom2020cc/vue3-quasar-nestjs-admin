按 YouTube 播放列表浏览（2026-10-09）

打开油管视频 ↗
  1. 选择已授权的频道，系统自动读取视频与播放列表，也可点击「获取 / 刷新」。
  2. 频道有播放列表时，显示与 YouTube 分类对应的封面卡片、列表名称、可见性和视频数量；可以搜索列表。
  3. 点击卡片进入该列表，按原有列表顺序查看视频；点击视频标题或「视频详情」查看完整信息，点击「返回播放列表」返回分类。
  4. 「全部视频」保留频道的所有上传视频，包括未加入任何播放列表的视频。表格显示「所属列表」，一个视频属于多个列表时全部列出，点击列表名可进入；未归类显示「未加入播放列表」。表格不再显示可见性列，完整描述仍可通过右侧「视频详情」查看。频道没有播放列表时，不显示播放列表页签，直接显示视频。

播放列表读取失败时会显示错误与重试提示，不会当成“没有播放列表”。本功能只读取既有分类，不会创建或修改 YouTube 播放列表。

视频上传和展示：列表、标题与详情

打开视频发布 ↗ 打开油管视频列表 ↗

「视频发布」与「油管视频」都提供视频列表、视频标题和「视频详情」入口。

  1. 待上传视频：选择文件后查看待上传列表，单个视频默认用文件名作为标题，可修改标题和视频详情 / 描述。批量发布时，每个视频可以填写自己的标题与描述，点击「视频详情」可预览文件、尺寸和时长。
  2. 已上传视频：右侧「已上传视频列表 / 发布记录」可按标题或描述搜索；点击标题或「视频详情」，查看完整描述、本地视频预览、尺寸、时长和各平台发布结果。YouTube 记录保留原任务绑定的目标频道。
  3. 油管视频：选择频道后点击「获取视频」，查看分页列表、封面、标题、详情摘要、时长、发布时间、可见性和播放量。可按标题或描述搜索，点击标题或「视频详情」查看完整内容及点赞、评论等信息。

此步骤含账号或网络隐私，截图仅保存在本机，请按上述文字操作。

多账号管理：发布到另一个 YouTube 频道

打开平台配置 / 账号授权 ↗ 打开目标对象 / 测试用户 ↗

Google Cloud 的应用可以供不同频道授权使用。本系统分别保存每个频道的令牌，新增账号不会覆盖原频道。

  1. 在「平台配置 → YouTube 多账号 / 频道管理」点击「添加 YouTube 账号」。应用处于测试模式时，先将目标 Google 邮箱加入「目标对象 → 测试用户」。
  2. 由账号本人在 Google 页面登录，选择要发布的账号和频道并完成授权。返回系统后核对频道名称与 UC… 频道 ID。
  3. 原有授权已自动保留；如果显示「待识别频道」，点击「识别频道」即可。每个账号可以设置备注、停用或重新授权。
  4. 进入「视频发布」，勾选 YouTube，在「YouTube 目标频道（必选）」中选择频道，核对下方目标再提交。批量发布使用同一个所选频道。
  5. 进入「油管视频」可切换频道查看视频。新增或重新授权后点击「备份到根目录」，多账号授权会一起写入私密配置文件。
发布记录固定绑定所选频道。重试、查询和重复检测均按频道处理，上传前也会校验真实授权归属。旧任务没有频道绑定信息，需要重新选择频道创建任务。不要用「重新授权」切换该行的频道；增加另一个频道请点「添加 YouTube 账号」。

一、为什么油管最难弄

抖音 / 快手 / TikTok 都是在一个「开放平台网站」里直接建应用；但 Google 把这件事拆成了三层，而且还要单独配一个「同意屏幕」，所以步骤最多：

「项目」 → 「开通 API」 → 「OAuth 客户端」 → 「同意屏幕」

这里的「项目」就是 Google 里"一个应用"的容器，只是名字叫"项目"，别被绕晕。

二、第 0 步：翻墙准备（最重要）

打开 Google 检查浏览器连接 ↗
油管授权和发布，都需要后端服务器去调 Google 的接口（换 token、上传视频、查状态）。所以光浏览器能上 Google 不够，必须让后端程序也能上 Google。

授权失败：fetch failed 表示后端网络请求失败。本次排查发现是直连 Google 超时，但该错误也可能由 DNS、证书或连接中断引起，应结合实际检查判断。

检查后端的网络出口

  1. 确认浏览器能打开 Google，并确认后端也能访问 Google 令牌接口和 YouTube API。
  2. 若使用虚拟网卡（TUN），检查规则是否覆盖 Google 请求，并保留 localhost 的本地访问。
  3. 也可以只为 Node 后端显式设置代理。项目附带 start-backend-proxy.bat，适用于本机 Node.js 24+ 和已有的 127.0.0.1:7890 HTTP 代理；使用前先停止原后端，前端保留运行。其他电脑需按实际端口配置。
不必一律切换到全局模式，也不必一律关闭系统代理。关键是后端请求实际能够连通 Google。重启后端后需从系统重新点击「授权」，旧回调地址中的 code / state 不能复用。

三、第 1 步：创建 Google Cloud 项目

打开当前项目 ↗ 新建 Google Cloud 项目 ↗
  1. 打开 Google Cloud 控制台，用有项目管理权限的 Google 账号登录；它可以与实际发布频道的账号不同。
  2. 看页面最顶部中间，点「选择项目」→ 弹窗右上角「新建项目」。
  3. 项目名随便起，比如 video-upload，点「创建」。
  4. 等顶部那行显示你刚起的项目名，再进行下一步。

四、第 2 步：开通 YouTube Data API

打开 YouTube Data API v3 ↗ 查看已启用的 API ↗
  1. 左侧菜单 →「API 和服务」→「已启用的 API 和服务」→ 点「＋ 启用 API 和服务」。
  2. 搜索框输入 YouTube Data API v3，点进去，点「启用」。

五、第 3 步：配置 OAuth 同意屏幕（新版界面）

打开品牌 / 同意屏幕 ↗ 打开目标对象 / 测试用户 ↗ 打开数据访问 / 权限范围 ↗
Google 已经改版了！网上很多老教程写的「选 External → 点 Create」是老版本的按钮，新版里找不到。新版把这一步拆成了左侧菜单里的几个页面。

新版在 左侧菜单 有这些项（在「API 和服务」里，也可能叫「Google Auth Platform」）：

Overview      （总览）
Branding      （品牌信息：应用名、支持邮箱）
Audience      （受众：老版的 External / Internal 在这里）
Clients       （客户端：就是"凭据 / Client ID"）
Data access   （数据访问：权限 scope）
Security

① 点左侧「Branding」

打开品牌 / 同意屏幕 ↗
  1. App name（应用名）：随便，比如 video-upload
  2. User support email（支持邮箱）：填你自己的邮箱
  3. 点 Save

② 点左侧「Audience」（老版的 External 在这里）

打开目标对象 / 测试用户 ↗
  1. 把受众类型选成 External。
  2. 找到 Test users，点「Add users」，填实际要授权发布的 Google 账号邮箱。
  3. 点 Save。
为什么要加"测试用户"：没正式上架的应用，Google 只允许"测试用户名单"里的人授权，不加自己就授权不了。

六、第 4 步：创建 OAuth 客户端，拿 Client ID / Secret

打开 OAuth 客户端 / 回调设置 ↗ 创建 OAuth 客户端 ↗
  1. 点左侧「Clients」，点「Create OAuth client」。
  2. Application type 选 Web application。
  3. 名称随便。
  4. 重点填下面的两个框（别填错框）：
最容易填错的一步！ 有两个长得很像的框，很多人把回调地址贴进了错的框里：
字段填什么
Authorized JavaScript origins
（授权 JavaScript 来源）		 留空，什么都不填（它只接受域名、不能带路径）
Authorized redirect URIs
（授权重定向 URI）		 填下面这一行（点「+ Add URI」再贴）： 
http://localhost:5001/platform/youtube/oauth/callback

填好后点 Create，弹窗会显示两个值，复制下来别关：

  • Client ID（客户端 ID）→ 对应系统的 appId
  • Client Secret（客户端密钥）→ 对应系统的 appSecret

七、第 5 步：填进系统「平台配置」页

打开平台配置 / 账号授权 ↗
  1. 打开我们系统的「平台配置」页：本地平台配置页面 ↗（若要求登录，用 admin@qq.com / admin123）。
  2. 找到「油管 YouTube」这一行，点右边的「配置」按钮。
  3. 首次配置只需手动填写这两项（已有令牌无需清空）：
    • 应用ID（client_key / client_id） ← 粘贴 Client ID
    • 应用密钥 client_secret ← 粘贴 Client Secret
  4. 点「保存」。

八、第 6 步：点「授权」完成授权

打开平台配置 / 账号授权 ↗ 打开目标对象 / 测试用户 ↗
  1. 回到表格，油管 YouTube 那一行点「添加账号」，或在下方频道管理点「添加 YouTube 账号」，浏览器跳转到 Google。
  2. 选你刚才加进"测试用户"的那个 Google 账号。
  3. 大概率会弹红字警告 "Google 未验证此应用"：
    • 点左下角「高级 / Advanced」
    • 再点「前往 xxx（不安全）/ Go to xxx (unsafe)」
  4. 核对应用身份与所选账号，确认授权 youtube.upload（视频上传）和 youtube.readonly（读取频道）、youtube.force-ssl（包括管理播放列表）权限。
  5. 授权成功会自动跳回系统，弹成功提示，下方频道管理出现对应频道。

九、成功标志

打开平台配置 / 账号授权 ↗ 打开视频发布 ↗ 打开油管视频列表 ↗
  • 页面弹出：「YouTube 频道授权已保存，其他频道授权保持不变」
  • 「YouTube 多账号 / 频道管理」显示正确的频道名称、频道 ID 与 「可选择发布」 状态
  • 访问令牌和刷新令牌会自动保存；刷新令牌失效或授权被撤销时，需要重新授权。

授权成功后，回「视频发布」页选一个横屏或竖屏视频，勾选「油管 YouTube」，再选择目标频道，核对名称和频道 ID 后提交。

十、易错点汇总（踩坑大全）

打开目标对象 / 测试用户 ↗ 打开 OAuth 客户端 / 回调设置 ↗ 打开平台配置 / 账号授权 ↗
坑现象 / 原因解决办法
fetch failed 点授权后报「授权失败：fetch failed」，后端连不上 Google 检查后端的代理、DNS 与连接错误；本例使用虚拟网卡和规则模式后成功。也可为 Node 后端显式指定可用代理。
找不到 External → Create Google 改版了，老教程的按钮没了 改去左侧菜单 Branding + Audience 配置
回调地址填错框 报 "Invalid Origin: must not contain a path" 回调地址填在 Authorized redirect URIs，JavaScript origins 留空
回调地址不匹配 Google 报 redirect_uri_mismatch 填的和系统里一字不差：http://localhost:5001/platform/youtube/oauth/callback
"应用未验证" 授权时弹红字警告 点「高级」→「前往 xxx（不安全）」继续
授权不了 / 账号被拒 账号没加进测试用户 去 Audience → Test users 加自己的邮箱
后端没启动 点授权后回调地址打不开 确保后端跑在 5001 端口（回调地址就是后端的地址）

横屏、竖屏均可发布：选择“窄屏（竖屏）”后 YouTube 仍可选，单个和批量发布均支持。旧版“仅宽屏”是项目筛选配置的问题，已修正。Shorts 分类由 YouTube 判断，参见官方说明。

发布视频时选择或新建播放列表（2026-10-09）

  1. 打开视频发布，选择 YouTube 平台和目标频道。
  2. 在“所属播放列表”中选择已有列表。留空表示不加入列表；切换频道会自动清空原选择，并加载新频道的列表。批量发布时，所有 YouTube 视频使用同一个列表。
  3. 需要新列表时点“新建列表”，输入名称并选择私密、不公开或公开，再点“创建并选择”。这一步会立即在所选 YouTube 频道创建列表，即使尚未发布视频，列表也已存在。列表可见范围不改变视频自身可见性。
  4. 填写视频标题和详情，确认频道及列表后点击发布。任务详情显示所属列表和是否已加入。视频转码完成后加入列表；如果这一步失败，可修复授权或网络后点重试，系统继续处理已上传的视频，不重新上传。

旧账号可能需要重新授权：创建列表和添加视频需要 youtube.force-ssl 权限。若提示缺少播放列表管理权限，在平台配置 → YouTube 账号管理中对该频道重新授权。必要时在Google 数据访问权限添加此范围，再返回应用重新授权。授权完成后重新备份本地私有配置。

如果创建请求中断，请先刷新列表确认是否已创建，再决定是否重试，避免重名列表。已经成功发布的视频仍按原规则去重，不能通过再次发布把它移动到另一列表。
